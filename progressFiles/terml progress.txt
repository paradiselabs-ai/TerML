To create an helpful AI assistant that permanently resides in your terminal (starting with MacOS and possibly expanding to other OS's). The AI will always be there, ready for conversation, to explain the output the terminal gives you, to give you advice on what command you should enter into the terminal next based on what you are trying to do. User's, after installing TerML should be able to call it with a specific command directly into the terminal you are in, and can read the terminal history (up to the last 20(?) commands). However after being called TerML   remains silent unless asked to do something.
There should be specific commands for TerML like:

-$ terml explain (explains the most previous output from the terminal)

-$ terml suggest (suggests a next command to give the terminal based on what it has seen from your terminal history so far)
-$ terml -q chat ( -q for "quick" - needs this argument to successfully pass this command. this will be the argument that opens an interactive shell (similar to opening vim or nano, or a python interactive shell), and here you can a quick, more in depth conversation with TerML to provide it with more info, explain to it what you are trying to do, get more specific advice if a command isn't working, etc.. so it is a quick chat session that is multi-turn (meaning it can have a coherent conversation, but upon closing the interactive chat (:q + ENTER) TerML will have no memory this chat (TerML being a claude model especially a new one, like clade 3.5 sonnet 20240620 would be perfect because it can right out of the box with an API key and an interface have a multi turn conversation but cannot retain memory after exiting the conversation. On top of that the model is great for coding and conversational ability). So because you wont have history of this quick interactive chat, be sure and take note of what it tells you! Whether by literally writing it down or using a quick text tool (since this will be on MacOS initially moped would be a great little text tool to record your conversation in this state with TerML [I may implement this kind of memory retention later].
$ terml debug - allows TerML to see why your last prompt did not get the results you wanted out of the terminal, perhaps you made a syntax error or you are simply using the wrong command, either way it will notice and suggest the correct command to use. If debug isn't working because TerML isn't able to perceive the intended output you were looking for calling a '$ terml -q chat' may be better for debugging just be sure to write down the answers it gives you! 

and last but not least:

-$ terml auto --with-user ("--with-user" is essential here, because auto will allow TerML to start to run commands on its own. However first TerML will have a quick chat with you, TerML: "What are you trying to achieve?" \n User: "to set up a directory for a new project" \n TerML: "What kind of project, and what tech stack to do you intend on using?" etc. etc... after it asks the questions it needs it will begin to automatically execute code into the terminal for you. the "--with-user" suffix wont let TerML actually execute any code without checking with the user and getting the "OK" from the user (ex (after writing terml auto --with-user and after having a quick conversation about what you want terml to do for you it would look something like this: 

-$ [code that TerML is intending to execute] (This code will *describes what the code will do*. Would you still like TerML to execute? [Y/n]: (then of course the user can choose Y/n or can press CTRL+C to exit the 'auto' mode from TerML. In order for TerML to work a working Anthropic API needs to be in the users ~/.zshrc or .zshprofile or .bashrc or .bashprofile, whatever the user has their shell configuration file named, it needs to have a working anthropic API in the the configuration profile.
